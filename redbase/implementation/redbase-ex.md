## Introduction

The final part of RedBase is a **personal extension** that adds a substantial new feature or implementation area beyond the basic project.

## Timetable

- proposal due: Sunday, May 17, 11:59 PM
- graded proposals posted: Wednesday, May 20
- final demos: Friday, June 5

## Scope and Modifications

The extension should require roughly the effort of a substantial earlier component such as RM. The proposal is a guide rather than a rigid contract; students may revise the plan as they learn more during implementation.

## The Proposal

The page says the proposal should include:

1. general functionality,
2. which components are modified,
3. overall design / diagram,
4. interface spec for major classes/methods,
5. informal behavior description,
6. a detailed demo plan or running example.

## The Implementation

Extension-specific names should begin with the prefix `EX`. General principles such as modularity, error handling, and documentation remain the same as earlier parts.

## Demo Details and Hints

The page gives practical demo guidance, including:

- arrive on time,
- bring printed `ex_DOC`,
- prepare a concise interactive script,
- demonstrate the extension clearly,
- submit new `.cc` and `.h` files immediately after the demo.

## Possible Extensions

The course page suggests many possible areas:

- variable-length records,
- blobs / text objects,
- clustering / partitioning,
- improved indexing,
- better join algorithms,
- query optimization,
- more SQL features,
- OLAP / XML,
- concurrency control,
- recovery,
- security,
- compression,
- versioning,
- networking,
- interfaces / UI / visualization.
